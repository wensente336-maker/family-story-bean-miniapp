# 家庭故事豆小程序 MVP：十阶段门禁开发计划

## 1. 执行规则

本计划是后续开发的唯一阶段基准，不以人日为依据，不跨阶段提前开发。

每个阶段严格执行以下流程：

1. 开始前说明本阶段目的、前置依赖和开发范围。
2. 仅实现本阶段范围，不擅自加入后续功能。
3. 完成后提交可查看的交付物、文件变更、测试结果和已知问题。
4. 阶段状态改为 **待用户确认**，停止继续开发。
5. 用户明确回复“确认阶段 N”后，阶段状态才改为 **已确认**，并开启下一阶段。
6. 用户提出修改时，仅修改当前阶段；重新提交验收，仍不进入下一阶段。

阶段状态只有五种：`未开始`、`进行中`、`待确认`、`已确认`、`阻塞`。

## 阶段 1：首页 UI 与产品入口

### 目的和作用

验证产品核心信息架构和视觉方向，让用户进入小程序后立刻理解三件事：可以上传家庭录音、AI 会发现家庭高光、结果可以生成漫画或播客。首页也是后续所有功能的统一入口和状态承载页。

### 前置依赖

- 已确认产品定位为“家庭故事豆”。
- 录音时长上限为 15 分钟。
- MVP 输出包含家庭漫画和家庭播客。
- 本阶段不依赖后端、数据库或真实 AI 服务。

### 开发任务

- 建立微信小程序基础目录和页面配置。
- 设计并实现首页视觉。
- 实现录音上传主按钮及入口弹层。
- 展示录音处理中状态、高光卡片和生成入口。
- 展示家庭成长时间线入口和隐私提示。
- 提供浏览器预览，便于不依赖微信开发者工具查看。

### 交付物

- 首页 WXML、WXSS、JavaScript 和页面配置。
- 微信小程序项目配置。
- 浏览器交互预览页。
- 首页交互说明。

### 完成标准

- JavaScript 与 JSON 语法校验通过。
- 首页在主流手机宽度下无关键内容遮挡或横向溢出。
- 上传按钮可打开上传入口弹层。
- 首页明确展示 15 分钟限制、家庭高光、漫画、播客和时间线。
- 当前为 UI 原型，所有模拟数据和未接入能力均有明确边界。

### 确认点

用户确认首页的信息结构、视觉方向和核心入口后，才启动阶段 2。

---

## 阶段 2：技术底座与数据契约

### 目的和作用

建立系统可持续扩展的工程骨架，提前固定客户端、服务端、数据库、异步任务和 AI 流水线之间的数据边界，避免后续模块采用不兼容的数据结构。

### 前置依赖

- 阶段 1 已确认。
- 确定后端运行环境和对象存储方案。
- 确定开发、测试和生产环境的配置方式。
- 可暂时没有正式微信 AppID，但需使用可替换配置。

### 开发任务

- 建立后端 API 工程、AI Worker 工程和环境配置。
- 建立数据库迁移机制。
- 定义用户、家庭、成员、录音、转写片段、高光、故事板、作品和任务的数据模型。
- 定义统一 API 响应、错误码、鉴权头和请求追踪 ID。
- 定义故事板 JSON Schema、任务状态机和 pipeline 版本字段。
- 提供 Mock API，使小程序可以在无真实服务时联调。
- 建立基础自动化测试和持续集成检查。

### 交付物

- 可启动的 API 服务与 AI Worker 骨架。
- 数据库 Schema 和首版迁移文件。
- OpenAPI 或等价接口契约。
- 故事板 JSON Schema。
- 环境变量模板、启动文档和 Mock 数据。

### 完成标准

- 新环境按文档可一次启动 API、数据库、Redis 和 Worker。
- 数据库迁移可正向执行并可回滚。
- 小程序可通过 Mock API 获取首页、任务和高光示例数据。
- 所有核心实体均有稳定 ID、所属家庭和创建/更新时间字段。
- API 契约测试通过，错误响应格式保持一致。

### 确认点

向用户展示架构、数据模型和 Mock 联调结果；用户确认后启动阶段 3。

## 阶段 3：微信登录与家庭空间

### 目的和作用

建立真实用户身份与家庭数据隔离。后续录音、人物、漫画和播客必须明确归属于某个家庭，任何家庭都不能访问其他家庭的数据。

### 前置依赖

- 阶段 2 已确认。
- 微信小程序测试号或正式 AppID 可用。
- 后端可以安全保存微信身份映射和会话。
- 数据库迁移能力正常。

### 开发任务

- 实现微信 `code` 登录和后端会话换取。
- 实现令牌过期、刷新或重新登录机制。
- 实现首次进入时创建家庭。
- 实现家庭名称和成员昵称管理。
- 实现家庭级数据访问中间件。
- 完成首页、家庭页及后续页面路由骨架。
- 增加未登录、家庭不存在和无权限状态页面。

### 交付物

- 微信登录接口和客户端登录流程。
- 家庭、家庭成员相关接口与页面。
- 家庭级数据隔离规则和自动化测试。
- 页面路由及登录拦截机制。

### 完成标准

- 用户首次进入可创建家庭，再次进入可恢复同一家庭。
- 连续 20 次登录、退出和重新进入无身份串联。
- 未登录请求 100% 被拒绝。
- 使用两个测试家庭进行交叉访问时，越权请求 100% 被拒绝。
- 登录失效后能回到可恢复状态，不丢失已提交操作。

### 确认点

向用户演示首次登录、创建家庭、再次进入和跨家庭拒绝；用户确认后启动阶段 4。

## 阶段 4：15 分钟录音上传

### 目的和作用

建立 AI 流水线稳定、可信的输入入口。客户端提示不能作为安全边界，服务端必须验证真实格式、时长、归属和上传完整性。

### 前置依赖

- 阶段 3 已确认。
- 对象存储和临时上传凭证可用。
- 小程序上传域名已配置。
- 明确支持的首版格式：MP3、M4A、WAV、AAC。

### 开发任务

- 实现小程序文件选择和客户端预检查。
- 后端创建录音记录并签发短期上传凭证。
- 小程序直传对象存储并上报上传完成。
- 服务端检测真实媒体类型、音频时长和文件摘要。
- 拒绝超过 15:00 的录音和损坏文件。
- 实现上传进度、取消、失败重试和重复回调幂等。
- 首页使用真实录音数据展示处理卡片。

### 交付物

- 录音选择与上传页面。
- 对象存储直传和上传回调接口。
- 媒体校验模块。
- 录音列表、详情和删除草稿接口。
- 上传正常、失败和边界测试报告。

### 完成标准

- 5、10、15 分钟合法录音均可成功上传。
- 50 个合法样本上传成功率不低于 98%。
- 15:01、伪造扩展名、空文件和损坏音频 100% 被拒绝或进入明确失败态。
- 相同上传完成回调重复执行不产生重复录音记录。
- 上传失败后用户无需重新选择文件即可重试。

### 确认点

向用户演示合法上传、超时拒绝、失败重试和首页真实状态；用户确认后启动阶段 5。

## 阶段 5：异步任务与处理进度

### 目的和作用

把耗时的转写和内容生成从小程序请求中解耦，使用户关闭小程序后任务仍能继续，并保证服务重启、消息重复或模型超时时不会丢任务或重复生成。

### 前置依赖

- 阶段 4 已确认。
- Redis、任务队列和 Worker 环境可用。
- 阶段 2 定义的任务状态机已确认。

### 开发任务

- 实现任务入队、消费、心跳和超时。
- 实现 `UPLOADED → PREPROCESSING → TRANSCRIBING → ANALYZING → READY` 状态流转。
- 实现阶段进度、错误码和用户可理解的状态文案。
- 实现幂等键、最多两次自动重试和死信队列。
- 小程序前台轮询，进入后台后停止，再次打开恢复状态。
- 增加人工重跑和暂停新任务的运维开关。

### 交付物

- 异步任务服务和 Worker。
- 任务状态与进度接口。
- 小程序处理进度页。
- 任务重试、恢复和故障注入测试报告。

### 完成标准

- 小程序关闭后任务继续处理，再次进入可恢复状态。
- Worker 重启后已领取任务不会永久丢失。
- 同一队列消息重复投递不会产生重复结果。
- Redis 短时不可用恢复后任务可继续。
- 自动重试次数和最终失败原因可查询。

### 确认点

向用户演示完整状态流转、关闭恢复和故障重试；用户确认后启动阶段 6。

## 阶段 6：音频转写与说话人映射

### 目的和作用

把原始家庭录音转化为可检索、可定位、可区分人物的结构化时间线，为高光发现、漫画对白和播客剪辑提供可信底座。

### 前置依赖

- 阶段 5 已确认。
- ASR 服务选型和测试额度可用。
- FFmpeg 等音频处理能力可用。
- 准备包含成人、儿童、重叠说话和环境噪声的冻结测试集。

### 开发任务

- 音频转码、音量标准化和 VAD 切分。
- ASR 转写并保留逐句开始/结束时间。
- 说话人分离，输出 A/B/C 等临时人物。
- 用户将临时人物映射为爸爸、妈妈、孩子等家庭成员。
- 对低置信度转写进行提示并允许修改。
- 实现点击转写文本跳转播放对应原声。
- 保存模型、参数和 pipeline 版本。

### 交付物

- 音频预处理与 ASR Worker。
- 带时间戳和说话人标识的转写数据。
- 说话人映射与转写查看页面。
- 冻结样本评测报告。

### 完成标准

- 冻结测试集音频处理成功率不低于 95%。
- 任意转写句点击播放的定位误差不超过 1 秒。
- 无法判断人物时正确降级为 A/B/C，不擅自绑定真实身份。
- 用户修改转写或人物后，修改结果可稳定保存。
- 原始音频、转写片段和人物映射均严格归属当前家庭。

### 确认点

向用户演示一段 15 分钟录音的转写、人物映射、原声定位和修改保存；用户确认后启动阶段 7。

## 阶段 7：AI 高光发现与统一故事板

### 目的和作用

这是产品的核心智能层：从普通家庭对话中找到真正值得留下的片段，并转换成漫画和播客都能复用的统一故事结构，避免两条生成链路各自理解一次录音。

### 前置依赖

- 阶段 6 已确认。
- 故事板 JSON Schema 已冻结。
- 建立由两人独立标注并解决分歧的家庭高光评测集。
- 明确直接引语必须绑定原始时间戳。

### 开发任务

- 根据笑声、情绪变化、金句、转折、故事完整度和家庭成员参与度召回候选片段。
- 使用 LLM 对候选片段重排并生成 Top 3。
- 为每段生成标题、场景、人物、开场、转折、结尾和情绪曲线。
- 为所有直接引语保存原始转写和音频时间戳引用。
- 实现高光选择页：试听、保留、删除、调整起止位置。
- 保存用户选择行为，为后续个性化积累反馈。

### 交付物

- 高光召回、评分和重排模块。
- 统一故事板生成模块。
- Top 3 高光确认页面。
- 高光黄金集和评测报告。

### 完成标准

- 10 个家庭、至少 50 段录音中，Top 3 至少包含一个用户保留片段的比例不低于 70%。
- 所有家庭成员直接引语的来源可追溯率为 100%。
- AI 虚构家庭成员直接引语为 0。
- 调整后的片段播放边界和故事板引用同步更新。
- 同一 pipeline 版本对同一输入能得到结构稳定、可解释的结果。

### 确认点

向用户演示真实录音的 Top 3、故事板、原声证据和调整操作；用户确认后启动阶段 8。

## 阶段 8：四格家庭漫画

### 目的和作用

把已确认的家庭高光转化为直观、易保存、易分享的视觉故事，验证“真实家庭声音可以生成有情感的内容作品”这一核心价值。

### 前置依赖

- 阶段 7 已确认。
- 图像生成服务可用，商业使用边界明确。
- 家庭角色采用卡通人物卡，不进行真人级人脸复刻。
- 已明确漫画中文字采用后置排版，不由图像模型直接生成。

### 开发任务

- 建立家庭成员卡通人物卡。
- 将统一故事板拆分为四格分镜。
- 为每格生成画面提示词和角色约束。
- 生成无文字画面，服务端后置叠加标题、旁白和对白。
- 实现漫画预览、修改文字、单格重新生成和长图保存。
- 每格绑定对应原声片段播放入口。
- 保存模型、提示词和作品版本。

### 交付物

- 家庭人物卡页面。
- 四格漫画生成 Worker。
- 对白排版与长图合成模块。
- 漫画预览和编辑页面。
- 作品生成评测报告。

### 完成标准

- 至少 30 次生成中，首次生成成功率不低于 90%。
- 人物数量明显错误率低于 5%。
- 漫画直接对白与真实转写一致率为 100%。
- 单格重新生成不会修改其他三格。
- 漫画长图可保存，并能从每格播放正确原声。

### 确认点

向用户展示不少于 3 个真实故事生成的漫画、编辑过程和原声播放；用户确认后启动阶段 9。

## 阶段 9：家庭播客

### 目的和作用

把多个家庭高光编排成可以完整收听的节目，在保留真实笑声和真实原声的前提下，用 AI 旁白补足上下文，形成比单个录音片段更有叙事感的家庭记忆。

### 前置依赖

- 阶段 8 已确认。
- 阶段 7 的故事板和原声引用稳定。
- TTS 服务和音乐素材可用，授权范围明确。
- 明确不克隆家庭成员声音，TTS 只生成主持人旁白。

### 开发任务

- 允许用户选择 1–3 个高光并调整顺序。
- 生成节目开场、转场、家庭金句和片尾脚本。
- 从原始录音无损裁剪高光原声。
- 使用 TTS 生成主持人旁白。
- 使用 FFmpeg 完成降噪、响度统一、音乐压低和混音。
- 实现播放器、节目封面、脚本调整和重新混音。
- TTS 失败时降级为无旁白原声精剪版。

### 交付物

- 播客脚本生成模块。
- 原声裁剪、TTS 与音频混音 Worker。
- 播客创建、进度和播放页面。
- 节目封面及成品文件。
- 音频质量与生成成功率报告。

### 完成标准

- 至少 30 次生成中，首次生成成功率不低于 90%。
- 正常成品时长控制在 2–3 分钟。
- AI 旁白和家庭真实原声在数据和 UI 中可明确区分。
- 真实原声片段均可回溯到原始录音位置。
- 调整高光顺序后可以重新生成，且不产生重复任务或重复扣费。

### 确认点

向用户演示不少于 3 期播客、脚本编辑、重新混音和降级版本；用户确认后启动阶段 10。

## 阶段 10：家庭时间线、隐私与全链路验收

### 目的和作用

把一次性生成工具变成可长期使用的家庭记忆产品，同时完成发布前必须具备的数据保护、删除、分享控制、性能监控和真实家庭验证。

### 前置依赖

- 阶段 9 已确认。
- 漫画和播客两条生成链路稳定。
- 隐私保留策略、分享规则和灰度家庭范围已明确。

### 开发任务

- 实现按日期、家庭成员和内容类型浏览成长时间线。
- 实现作品详情、私密签名 URL、可撤销分享和过期时间。
- 实现删除单个作品、原始录音和整个家庭空间。
- 实现原始录音默认 7 天过期删除。
- 完成数据库、缓存、对象存储和派生内容的级联删除。
- 增加任务成功率、阶段耗时、P95、模型成本和删除结果监控。
- 完成真机回归、历史回放、性能测试、故障注入和回滚演练。
- 使用 10 个家庭、每家至少 5 段录音进行灰度验证。

### 交付物

- 家庭成长时间线和作品详情页。
- 私密分享与撤销机制。
- 数据过期及级联删除任务。
- 监控、告警和发布回滚开关。
- 全链路测试报告、灰度报告和最终验收清单。

### 完成标准

- 上传成功率不低于 98%。
- 录音完成高光分析的成功率不低于 95%。
- 15 分钟录音从上传完成到高光可选的 P95 不超过 5 分钟。
- 漫画、播客首次生成成功率均不低于 90%。
- 进入高光页后完成至少一种作品生成的用户比例不低于 60%。
- 跨家庭访问 100% 被拒绝。
- 删除请求在 15 分钟内完成数据库、缓存和对象存储清理，成功率 100%。
- 分享链接过期或撤销后 100% 不可访问。
- P0/P1 缺陷清零，灰度期间无隐私事件。

### 确认点

向用户提交完整体验版、测试证据、灰度结果、已知风险和发布建议。用户最终确认后，MVP 才视为完成并允许进入后续产品迭代。
