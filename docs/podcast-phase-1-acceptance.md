# 家庭播客新版阶段 1 验收记录

## 阶段结论

阶段 1“产品主线切换与技术契约”已完成，等待产品确认。未开始阶段 2 的声音素材确认台开发。

## 目的和作用

将 Web MVP 从漫画/播客双主线收敛为声音播客单主线，同时保留历史漫画数据和回滚能力；为后续声音素材、AI 串讲、混音、封面与标签建立不依赖绘本的数据契约。

## 已满足的前置依赖

- 现有 Web、API、PostgreSQL、对象存储与本地异步处理环境可运行。
- 现有录音、转写、高光、播客、漫画和绘本数据未删除。
- 新方案与 8 阶段开发计划已经获得用户确认。

## 交付物

### 产品入口与回滚开关

- 首页仅显示“生成家庭播客”，主导航“故事”改为“播客”。
- 高光页只显示家庭播客生成入口。
- 过程文案由“生成故事板”调整为“整理声音素材”。
- `VITE_ENABLE_COMIC_CREATION=false` 默认关闭漫画创建入口；设为 `true` 可恢复旧入口。
- `COMIC_CREATION_ENABLED=false` 默认关闭后端漫画新增和重画接口。
- 历史漫画路由继续可访问，并以只读归档页展示、导出和私密分享。

### 播客 v2 技术契约

- `PodcastMaterialData`：录音、逐字稿、说话人、片段角色和时间范围。
- `PodcastMaterialSetData`：同一录音内 1～3 个有序素材及确认版本。
- `PodcastPlanData`：第三人称解说、原声引用、音色和音乐风格。
- `PodcastVersionData`：策划、成品、封面、标签和生成状态的聚合契约。
- `CoverAssetData` 与 `PodcastTagData`：封面和标签契约。
- 前后端均已建立对应类型。

### 状态机

`DRAFT → CONFIRMED → GENERATING → COMPLETED/FAILED`

- `CONFIRMED → DRAFT`：解锁并创建修改版本。
- `FAILED → DRAFT/GENERATING`：修改或重试。
- `COMPLETED`：不可变完成版本；修改时创建新版本。

状态机以 JSON 契约和后端枚举双重保存，并由自动化测试验证完全一致。

### 数据库迁移

已新增并应用 `0015_podcast_mvp.sql`：

- `podcast_projects`
- `podcast_versions`
- `podcast_material_sets`
- `podcast_materials`
- `podcast_plans`
- `podcast_cover_assets`
- `podcast_tags`
- `podcast_version_tags`

迁移提供对应 down 文件，未改写既有 `creations`、`podcast_segments` 或绘本表。`legacy_creation_id` 用于后续兼容既有播客成品。

## 已知边界

- 阶段 1 只建立 v2 数据契约和产品入口，现有播客生成 API 仍沿用 v1 同步生成逻辑。
- 声音素材的逐字稿修订、人物确认、片段角色与版本保存属于阶段 2。
- 第三人称 AI 串讲生成属于阶段 3。
- 历史漫画仍可导出和创建私密分享链接，但内容本身不可新增或重画。
