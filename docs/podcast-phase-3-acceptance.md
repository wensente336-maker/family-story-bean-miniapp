# 家庭播客新版阶段 3 验收记录

## 阶段结论

阶段 3“AI 第三人称串讲引擎”的结构化生成、强制溯源、安全降级、API 和预览页面已完成，等待产品确认。当前演示声音素材仍保持草稿状态，系统不会越过用户确认门禁生成真实策划。

## 目的和作用

把已锁定的声音事实组织成连续的第三人称声音故事线，同时确保家人原声不被改写、所有解说均有依据、模型异常不会产生不可追溯内容。

## 已完成开发任务

- 新增四种串讲风格：温暖陪伴、轻松有趣、成长记录、家庭纪实。
- 原声按照用户确认顺序进入故事线，原声文字逐字复制 `confirmed_text`。
- 开场、转场和收尾均绑定一个或多个 `source_material_id`。
- 新增六项硬校验：段号连续、全段可追溯、原声逐字一致、原声顺序一致、解说不复制原声冒充引语、分享权限继承。
- 新增 OpenAI 兼容模型适配器；服务地址、模型和密钥均由服务端环境变量提供，不写入策划数据。
- 模型未配置、超时、拒绝、非法 JSON 或校验失败时，自动切换到可追溯安全脚本。
- 同一声音素材版本和同一风格的重复生成请求幂等返回现有草案；切换风格才递增草案修订号。
- 新增串讲预览页，区分 AI 解说与家庭原声，并展示每段来源、人物和时间范围。
- 素材未确认时返回 `PODCAST_MATERIALS_NOT_CONFIRMED`，预览页引导用户返回确认台。

## API

- `GET /v1/recordings/{recording_id}/podcast-plan`
- `POST /v1/recordings/{recording_id}/podcast-plan/draft`

本阶段复用阶段 1 已创建的 `podcast_plans` 表，无新增数据库迁移。

## 当前运行方式与边界

- 未配置外部大语言模型时，默认使用 `safe-template / sound-story-safe-v1`，保证本地 MVP 可运行和可追溯。
- 配置 `PODCAST_SCRIPT_ENDPOINT`、`PODCAST_SCRIPT_API_KEY`、`PODCAST_SCRIPT_PROVIDER` 和 `PODCAST_SCRIPT_MODEL` 后，优先调用兼容模型；任何不安全输出仍会被丢弃并降级。
- 当前只生成草案，不允许编辑、试听 TTS、确认或启动混音；这些能力属于阶段 4 和阶段 5。
- 当前真实演示素材仍为草稿，没有代替用户确认或修改其内容。
