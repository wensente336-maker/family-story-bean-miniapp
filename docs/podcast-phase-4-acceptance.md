# 家庭播客新版阶段 4 验收记录

## 阶段结论

阶段 4“脚本审核、试听与版本锁定”已完成，等待产品确认。系统允许用户在产生完整混音成本之前检查和修改策划；确认只锁定版本，不会提前启动阶段 5 的完整音频制作。

## 目的和作用

把阶段 3 的机器草案变成用户明确认可的播客制作清单，让用户最终决定 AI 要说什么、保留哪些家庭原声、采用什么音色和音乐氛围。

## 已完成开发任务

- 将串讲预览页升级为完整策划审核台。
- 按最终播放顺序明确区分“AI 第三人称解说”和“家庭原声”。
- 支持修改标题、简介、所有 AI 解说文字、AI 解说音色和背景音乐风格。
- 支持调整段落顺序，同时保持家庭原声的时间顺序约束。
- 家庭原声文字保持只读，可按确认的开始和结束时间回听。
- AI 解说可生成最长 120 字的短试听；试听前自动保存并重新校验当前草案。
- TTS 试听优先使用豆包自然音色，不可用时允许系统音色降级，并将试听资产写入私有短时签名地址。
- 相同文字与音色的试听结果使用内容摘要缓存，避免重复调用和重复计费。
- 保存或确认时重新执行来源、原声逐字一致、顺序、隐私和敏感信息校验。
- 新增“确认并锁定策划”门禁；确认后页面只读，重复确认幂等返回同一版本。
- 若需修改已确认版本，必须回到声音素材阶段创建新修订，不覆盖已锁定策划。

## API

- `PUT /v1/recordings/{recording_id}/podcast-plan`
- `POST /v1/recordings/{recording_id}/podcast-plan/narration-preview`

本阶段复用 `podcast_plans` 和 `podcast_versions` 现有字段，无新增数据库迁移。

## 完成标准与证据

| 完成标准 | 结果 | 验收证据 |
|---|---|---|
| 一个页面检查完整播放顺序 | 通过 | 解说与原声卡片按 `segment_index` 展示 |
| 原声与 AI 解说 100% 明确区分 | 通过 | 独立类型、颜色、图标、编辑和试听行为 |
| 家庭原声不可被改写 | 通过 | 前端只读，后端逐字校验，篡改请求返回 422 |
| 草案可编辑和保存 | 通过 | 标题、简介、解说、音色、音乐和顺序均可保存 |
| 短试听不触发完整混音 | 通过 | 独立试听服务，仅合成选中的解说段 |
| 未确认策划不能进入正式制作 | 通过 | 本阶段无完整渲染入口，版本保持 DRAFT |
| 确认后不可原地修改 | 通过 | 策划和播客版本同步置为 CONFIRMED，后续草稿更新返回 409 |
| 重复确认不产生重复版本 | 通过 | 已确认状态幂等返回当前版本 |

## 当前边界

- 完整 MP3、背景音乐压低、连续拼接、失败重试和原声精剪降级属于阶段 5。
