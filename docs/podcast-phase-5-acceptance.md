# 新版阶段 5 验收：异步音频制作与混音

## 目的与作用

把用户已确认的“声音素材 + 第三人称串讲策划”转换为一个可播放、可下载的 MP3 家庭播客。制作在后台任务中执行，用户可看到进度、失败原因并安全重试。

## 前置依赖

- 阶段 2 的声音素材集已确认。
- 阶段 4 的串讲策划已确认并锁定。
- 原始录音私密存储资产仍可读。
- FFmpeg/FFprobe 可用；真人感解说优先使用火山引擎 TTS。

## 本阶段交付物

1. `podcast_render_jobs` 异步任务表，包含进度、执行租约、错误、重试次数与幂等键。
2. 可切换的本地后台任务 / Celery `podcast` 队列调度。
3. 混音流水线：解说合成、原声精确裁剪、顺序串联、自有背景音床、人声侧链压低、响度标准化与 MP3 导出。
4. 完整的播放时间线和渲染元数据，保留每段家庭原声的来源标识。
5. Web 制作页 `/recordings/:id/render`：启动、进度轮询、失败重试、试听、下载和纯原声兜底说明。
6. 数据库迁移 `0017_podcast_render_jobs.sql`。

## 核心规则

- 未确认的策划不得生成音频。
- 同一锁定版本按内容指纹幂等，重复点击不重复渲染。
- 原声文本必须与已确认素材一致，裁剪边界只从锁定素材读取。
- 任何一段 TTS 在串讲中途失败时，整集统一重制为纯原声版，不交付“部分解说”的割裂成品。
- 背景音在人声出现时自动压低，且不使用未授权的外部音乐资产。

## 完成标准与结果

- 数据库迁移已在本地 PostgreSQL 成功执行。
- 后端全量回归：190 项通过。
- 前端回归：17 项通过；TypeScript + Vite 生产构建通过。
- 30 组不同原声边界样本均保持精确的开始/结束时间。
- 幂等、故障重试、TTS 完全不可用和 TTS 中途不可用均已自动化验证。
- Web `http://127.0.0.1:4173/` 与 API `http://127.0.0.1:8000/health` 已恢复本地可访问。

## 用户验收路径

1. 打开已锁定的串讲策划页。
2. 点击“进入音频制作”。
3. 点击“开始制作家庭播客”，观察后台进度。
4. 完成后试听并下载 MP3，检查解说、原声、背景音的衔接。

注：现有真实演示录音的素材集仍保持 `DRAFT`，本阶段未代替用户确认或生成其音频。
