# 播客快捷管理与回收站

实现日期：2026-09-22。

## 使用方式

- 桌面端悬停作品卡片或键盘聚焦时，右上角出现「…」；触屏及手机宽度下常显。
- 菜单提供编辑、分享、删除。编辑直接定位现有标题表单，分享在列表弹窗中完成。
- 删除需确认，成功后卡片消失；失败时保留卡片并允许重试。
- 播客页顶部「回收站（N）」进入 `/podcasts/trash`。支持查看删除时间及单件恢复，不自动清除。
- 恢复保留作品内容、封面、标签、音频身份及原更新时间；旧分享链接保持撤销，需要重新分享。

## 实现边界

软删除标记位于 podcast_projects，同一作品所有版本一起隐藏。版本生成状态不变，不删除成品文件，也不改变现有原录音隐私保留策略。显式删除录音或家庭空间仍按现有级联删除规则执行。

删除、撤销分享、审计在同一数据库事务内完成；分享创建使用相同项目锁，避免并发创建遗漏。回收站作品禁止正常读取、元信息和封面修改、新建分享及新音频签名。恢复和删除均为幂等接口。

新签发的公共分享音频/封面请求再次校验分享状态；撤销后后续请求返回 404，响应禁止缓存。已经下载或已缓冲的媒体无法追回；升级前签发的通用短期媒体地址仍遵循原签名到期时间。

## 验证

- 前端 TypeScript/Vite 构建与 Vitest API 测试。
- 后端完整 pytest 回归；真实 PostgreSQL 集成测试使用独立随机 schema，结束清理测试数据。
- 实库覆盖：多版本整件回收、恢复前后内容一致、跨家庭操作拒绝、重复请求幂等、删除确认契约、旧分享不复活、10 轮分享/删除并发、审计写入失败时整笔事务回滚。
- Chrome 人工检查：菜单、列表内分享、Esc 关闭与焦点恢复、取消删除不改变 3 个现有作品、回收站空状态、编辑入口定位、390px 手机宽度。

实库测试命令（从 backend 目录执行）：

```sh
PODCAST_TRASH_DB_TEST=1 .venv/bin/python -m pytest tests/test_podcast_trash_integration.py
```

本地已应用 `0021_podcast_trash.sql` 并重启 API 服务。其他环境需先应用迁移再发布后端与前端。出现问题时可撤回前端新入口，但应保留支持 deleted_at 的后端过滤逻辑，防止回收站作品重新可见。迁移回退脚本在存在回收站作品时主动拒绝执行。
