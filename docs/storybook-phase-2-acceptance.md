# 沉浸式电子书阶段 2 验收：数据与版本底座

## 目的与作用

将阶段 1 的前端体验原型变成可持久化的家庭作品。后续配音、分享和 PDF 必须引用同一个书册版本，避免漫画重画后出现页面、声音与导出内容不一致。

## 前置依赖

- 阶段 1 的六页电子书体验已确认。
- 漫画作品、四格分镜、转写片段和真实原声时间轴已存在。
- PostgreSQL 已完成 0001–0010 迁移。

## 本阶段交付

- `storybooks` 书册主记录，保存当前版本与生命周期状态。
- `storybook_versions` 不可变版本快照，保存 schema、来源漫画版本和完整 Manifest。
- Manifest v1 固定封面、故事页、封底、分镜版本、旁白、原声片段 ID 与时间轴。
- 创建/同步当前书册、读取当前版本、列出版本历史、读取指定历史版本四组接口。
- Web 阅读器优先消费服务端 Manifest；接口暂不可用时保持阶段 1 原型可读。
- 漫画重画后自动同步书册新版本，书册同步失败不会误报漫画重画失败。

## 完成标准与结果

- 第 11 号迁移已在本地 PostgreSQL 成功执行。
- 当前漫画生成书册 `c7a90e0b-eb33-4dfc-a1e4-7516e0a37fd6`，来源漫画版本为 9，共 6 页。
- 同一漫画版本连续同步两次仅保留 1 条版本记录，幂等验证通过。
- 三段真实原声分别绑定到页面 1–3，时间范围与转写片段一致。
- 创建、重复创建、版本列表和历史快照接口均返回 HTTP 200。
- 后端 94 项测试与前端 15 项测试全部通过，生产构建成功。

## 阶段边界

本阶段只建立数据与版本真相源。服务端音频资产、沉浸式分享页和印刷级 PDF 不在本阶段实现。
