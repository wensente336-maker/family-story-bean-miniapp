# 沉浸式电子书阶段 3 验收：声音优先创作链

## 目的与作用

先把用户标注的说话人、原话和时间边界固化为声音事实，再由后端围绕这条声音故事线完成二次创作和导演分场。漫画、解说、原声、字幕与混音必须来自同一份导演脚本，不能再从既有四格漫画反向拼接音频。

## 前置依赖

- 阶段 2 书册主记录、不可变版本和 Manifest v1 已确认。
- 逐字稿包含说话人映射、原始毫秒时间范围和用户确认的高光边界。
- 第 12 号迁移提供的私密原声裁片可正常生成并支持短时签名访问。

## 本阶段交付

- `storybook_story_plans` 保存声音事实、用户取舍、导演脚本、确认状态和修订号。
- 声音事实中的原话保持锁定，并保存说话人、原录音区间和是否入选。
- 导演脚本按故事语义拆幕，每幕同时定义故事作用、画面描述、图像提示词、解说文字、人物原声和音频顺序。
- Web 导演台允许用户确认原声取舍，并在生成最终绘本前查看完整场景安排。
- 未确认的故事线无法调用最终体验音轨接口；任何修改都会让旧体验音轨失效并清理对象文件。
- 服务端把 AI 解说、家庭原声和低音量背景音乐混成一条连续 MP3，而不是前端拼接多个音频文件。
- `storybook_experience_tracks` 持久化版本对应的体验音轨、故事线、场景范围和细粒度 cue sheet。
- `POST /v1/storybooks/{id}/experience-session` 返回短时签名播放地址、场景范围、文字 cue、解说音色和背景音乐信息。
- 前端以音频时间为唯一时钟：cue 决定当前文字，scene 决定当前画面；手动翻页则跳转到该幕的音频起点。
- 自动翻页、暂停/续播、原声/解说状态提示和弱动效都服从同一播放状态。
- 删除漫画、录音或家庭时，连续体验音轨纳入隐私级联清理。

## 完成标准

- 第 14 号迁移可在本地 PostgreSQL 正常执行和回滚。
- 真实测试书已从逐字稿生成 3 段人物原声事实和 7 幕导演脚本。
- 三段原声分别正确识别为苗苗、妈妈和爸爸，并保留原始时间边界。
- 场景按开场、环境、事件、人物原声、真实反应、喜剧落点和收束组织。
- 未确认草案请求最终体验音轨时返回 `STORY_PLAN_CONFIRMATION_REQUIRED`。
- 同一书册版本只生成并复用一条连续体验音轨。
- 接口返回的场景与 cue 时间单调递增，均落在音轨总时长内。
- 播放到不同 cue 时，页面、当前解说文字和“故事解说/家庭原声”状态同步更新。
- 手动翻页会 seek 到对应故事幕，而不是另起一段音频。
- 音轨支持 HTTP Range，签名地址过期后可重新申请会话。
- 后端、前端单元测试与生产构建全部通过，并完成一次真实书册的端到端播放验证。

## 阶段边界

本阶段完成声音事实、导演脚本、确认门槛和统一消费契约。当前四格资产只作为人物风格参考；真实图像模型根据每幕提示词重新生成画面，以及 PDF/分享成品更新，属于确认本阶段后的下一阶段。
