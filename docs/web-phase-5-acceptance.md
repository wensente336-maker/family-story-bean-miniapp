# Web 阶段 5 验收：异步任务与处理进度

状态：已确认

## 目的和作用

将耗时处理从 HTTP 请求中解耦，使用户关闭或刷新页面后任务仍能继续，并为阶段 6 的真实 ASR 提供可重试、可恢复、可观测的执行基座。

## 前置依赖

- Web 阶段 4 已确认。
- PostgreSQL、Redis 和 Celery Worker/Beat 可用。
- 阶段 2 的任务状态机和幂等键规则已冻结。

## 已交付

- 上传完成后幂等创建并投递 `RECORDING_PIPELINE` 任务。
- Celery 队列、Worker、Beat 心跳恢复、自动重试与死信队列。
- 数据库原子领取和执行令牌，防止重复消息生成重复结果。
- `CREATED → PREPROCESSING → TRANSCRIBING → ANALYZING → READY_FOR_SELECTION` 可观测状态流转。
- 任务详情、按录音查任务、人工重跑、流水线运维状态 API。
- Redis 短时故障时保留 `CREATED` 任务，轮询后机会性补投。
- `PIPELINE_ACCEPT_NEW_JOBS` 暂停新任务开关。
- Web 处理进度页：前台轮询、后台停止、恢复可见立即查询、刷新恢复、错误展示与人工重跑。
- 数据库迁移 `0005_async_jobs`，已验证升级、回滚、再升级。

## 验收结果

- 后端自动测试：48 项通过。
- Web 自动测试：8 项通过；TypeScript 与生产构建通过；npm 依赖审计 0 个漏洞。
- 真实 HTTP 回调再次调用：幂等返回原任务，状态 `READY_FOR_SELECTION`，进度 100%。
- 真实 Celery 重复投递：返回 `DUPLICATE_SKIPPED`，未重复执行流水线。
- 真实心跳超时恢复：发现 1 个失联任务，自动补投后回到 `READY_FOR_SELECTION` 100%。
- 队列不可用与恢复、暂停开关、故障注入、手工重跑均有自动化覆盖。
- 浏览器验收：进度页显示 100%、心跳和重试计数；刷新后从 API 恢复同一状态。

## 已知边界

- 阶段 5 验证的是异步执行基座，各状态目前由可观测模拟步骤驱动；真实转码、ASR、说话人分离在阶段 6 接入。
- 本地为单 Worker 验收配置；生产环境的多 Worker 容量、监控告警和托管 Redis 在阶段 10 完成。
- 任务主动取消不在 MVP 当前范围；失败任务可人工重跑。

## 确认门

用户确认完整状态流转、关闭/刷新恢复、幂等去重与故障重试后，才能启动 Web 阶段 6。
