# Web 阶段 8 验收：四格家庭漫画

状态：已确认

## 目的和作用

把用户已保留的家庭高光转换成可浏览、可局部修改、可保存分享的四格漫画。本阶段同时验证三条核心产品约束：四格人物设定一致、家人直接引语可溯源、重画某一格不破坏整个作品。

## 前置依赖

- Web 阶段 7 已确认。
- 高光的 `selection_state=kept`，且 `storyboard-v1` 完整包含场景、人物、叙事节点与原话来源。
- Web 鉴权、家庭级数据隔离和 HTTP API Client 可用。

## 已交付

- 新增 `creations` 漫画元数据和 `comic_panels` 四格分镜存储，迁移 `0008_comics` 可升级和回滚。
- 已保留高光可幂等生成四格漫画，未保留内容不允许生成。
- 每个漫画保存统一的 `visual_bible`：风格、配色、人物和一致性约束。
- 四格页在桌面端为 2×2，在手机端为单列；原话对白与 AI 旁白有明确标识。
- 单格重画只更新目标分镜的资产和版本，其他三格版本保持不变。
- 浏览器端 Canvas 生成 1080 px 竖版 PNG，包含标题、四格画面、对白、旁白和溯源标签。
- 已生成一组主漫画和第 2 格重画备选资产，人物服装、家庭关系与绘画风格保持一致。
- 家庭所有权校验覆盖漫画读取和单格重画。

## 验收结果

- “周日晚餐”已保留高光可生成 4 格完整漫画，共享同一份人物设定。
- 单条原话只出现在第 2 格，并绑定原转写片段 ID；其余文本均标识为故事旁白。
- 第 2 格可独立重画为 v2，第 1、3、4 格仍为 v1。
- 竖版长图已在浏览器中生成并下载为 1080×3479 PNG；实际图片复核确认长标题、对白、四格画面和溯源标签完整。
- 候选资产尺寸：四格主页 1374×1145；单格备选 1536×1024。
- 后端 70 项自动测试通过；Web 9 项自动测试通过；TypeScript 检查与生产构建通过；OpenAPI 已导出；npm 审计为 0 个漏洞。

## 已知边界

- 本阶段使用 Codex 内置图像生成工具生成候选资产，后端使用本地固定资产适配器。这足以验证交互和数据契约，但尚不能为任意新故事实时生成专属画面。
- 生产版还需接入可替换的生图 Provider、异步队列、超时/重试、内容安全、成本限额和对象存储。
- 现有长图为前端 Canvas 导出；移动浏览器的系统分享面板、服务端合成与二次编辑不在 MVP 范围内。

## 确认门

用户确认四格布局、人物一致性、原话溯源、单格重画与长图导出后，才能启动 Web 阶段 9。
