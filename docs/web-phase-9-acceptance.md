# Web 阶段 9 验收：家庭播客（真人感音色整改版）

状态：已确认（2026-09-20）

## 目的和作用

把 1–3 个用户已保留的家庭高光编排成可完整收听的家庭播客。节目使用普通 AI 主持人旁白补足上下文，同时保留真实的家人原声，两者在数据和 UI 中始终明确分开。

## 前置依赖

- Web 阶段 8 已确认。
- 阶段 7 的高光边界、统一故事板和原话引用稳定。
- 火山引擎豆包语音应用已开通大模型 TTS，并提供可用的 App ID / Access Token 或新版 API Key。
- FFmpeg、私有文件存储与本地降级音色可用。
- 已冻结“不克隆家人声音”约束。

## 已交付

- 数据库迁移 `0009_podcasts`：播客高光顺序、节目分段、原声来源与时间边界。
- 允许选择 1–3 个同一录音中已保留高光，并保存节目顺序。
- 生成主持人开场、故事转场、家人原声、回味和片尾脚本。
- 使用 FFmpeg 按毫秒边界剪辑原录音，进行高低频清理、响度统一、留白、串接和 MP3 编码。
- 新增可插拔的服务端 TTS 适配层，默认接入豆包 HTTP V3 大模型语音合成。
- 默认主持人为“小何 2.0”通用中文女声，24 kHz 生成后统一到 48 kHz 混音，不使用家人声音克隆。
- 兼容旧版 App ID / Access Token 和新版 API Key 两种服务端鉴权方式，凭证不进入 Web 构建产物。
- 云端 TTS 失败后仅降级一次，页面会显示备用提示；不会把系统音色标成真人感音色。
- 使用本地生成的双音环境床混音，不引入外部版权音乐。
- TTS 不可用或执行失败时，跳过旁白并产出 `original_only` 原声精剪版。
- 播客页包含节目封面、播放器、MP3 下载、原录音溯源试听、高光排序、开场/片尾编辑和重新混音。
- 以高光顺序和脚本生成请求指纹，相同重混请求幂等返回，不增加版本或重复渲染。
- 家庭所有权校验覆盖播客创建、读取、重混和短时签名播放地址。

## 验收结果

- 使用“周日晚餐”的已保留高光生成一期 72.46 秒播客，包含 5 个脚本分段和 1 段可溯源原声。
- 成品为 48 kHz、单声道、128 kbps MP3，平均电平 -16.3 dB，峰值 -1.9 dB。
- 浏览器完成播客生成、页面播放请求、回到 `3.3–7.0` 秒原录音试听和附件下载请求。
- 修改开场后重混成 v2；立即重复相同请求仍为 v2，幂等性通过。
- 后端 76 项自动测试、Web 10 项自动测试、TypeScript 检查与生产构建均通过；npm 审计为 0 个漏洞。
- 播客媒体评估数据见 `docs/podcast-audio-eval-report.json`。

### 2026-09-20 真人感音色整改验证

- 豆包 TTS 适配器、响应分块解码、服务端凭证隔离、失败降级和供应商标识均已实现。
- 后端 78 项自动测试通过，其中包含豆包分块音频解码和真人感音色混音测试。
- Web 10 项自动测试、TypeScript 检查与生产构建通过。
- `seed-tts-2.0` 服务权限已生效，使用“小何 2.0”生成 11.616 秒真人感主持人试听，原始返回为 24 kHz、单声道 MP3。
- 端到端验证已生成 13.418 秒家庭播客，包含 2 段豆包主持人旁白、1 段可溯源原声和环境床混音。成品为 48 kHz、单声道、128 kbps MP3，`tts_provider=volcengine-doubao`、`tts_fallback_used=false`。

## 已知边界

- 当前生成在 API 请求内同步完成；生产版必须迁移到独立生成 Worker，提供心跳、超时、重试、取消与真实进度。
- 当前应用只开通 `seed-tts-2.0`，未开通 1.0 资源；当前音色和产品链路不依赖 1.0，不影响 MVP。
- 本地系统音色只是可用性降级适配器，不作为商业上线音色。
- 当前只有一条授权的本地演示录音，因此尚未满足“30 次真实生成成功率”和“不少于 3 期真实播客”的产品化验收样本。
- 单高光被定义为 45–90 秒的“高光短篇”；2–3 分钟标准需在选择 2–3 个高光时评估。
- 音乐 ducking、更自然的停顿、多主持人音色、服务端封面文件与波形预览尚未实现。
- 重混会保留带版本号的音频文件，但数据库目前只展示最新脚本，尚未提供历史版本回滚界面。
